# 智维 · 云管平台（CloudOps）· 与智擎融合方案

> 版本：**v2.0** | 2026-09-30
> 关联文档：`智维集成平台-MVP方案.md`、`APM监控产品-MVP方案.md`、`multi-site-deployment.md`、`zhidun/README.md`
> 背景：自有 3 台轻量云服务器（无法运行 K8s），需要 Web 运维中台（可视化建站/发布/多机管理）。**它既是自用基础设施，又是未来可开源/售卖的产品。**
>
> **修订记录**
> - v1.0：初版，路线为"自研 node-agent 全栈替代 Coolify/1Panel"。
> - **v2.0（重大方向修正）**：放弃"自研竞品"路线，改为**「自研控制台 + 开源引擎（Coolify）+ 差异化层」**三层架构。修正依据（已联网核实，2026-09-30）：
>   1. Coolify 是 **Apache-2.0** 全开源（无 open-core 陷阱、无付费墙功能），**可自由商用、可在其上构建付费服务，无 copyleft 传染**——与它为敌是战略错误，与它为伍才是正解；
>   2. Coolify 有**完整 REST API**（约 189 个操作，token 分 read/write/deploy/root 权限，按 team 隔离），原生支持**多机 SSH 编排**、280+ 一键服务、自动 SSL——部署引擎这个轮子已经造得极好；
>   3. Coolify 的**已验证短板**恰好是智擎的已有资产能补的：权限模型粗糙（仅 admin/member 两级，细粒度 RBAC 官方排期到 v5）、无中文生态、无 APM/SSL 联动、备份升级粗糙（来源：Hetzner 官方博客评测、coolify.io 官方 API 文档）；
>   4. 1Panel 是 **GPL-3.0**：当工具用没问题，但**绝不能改它的代码做闭源商业产品**——进一步印证它只能是过渡件。

---

## 0. 核心结论（v2 一句话版）

> **不重造 Coolify。造 Coolify 没有的那一层：多租户控制台 + 中文生态 + 发布即监控。**
> 架构关系类比：**Rancher 之于 K8s**——Rancher 从不重造 K8s，它做企业级管理层，一样成了大公司。

---

## 1. 战略框架：三层切蛋糕

```
┌─────────────────────────────────────────────────────────────┐
│ 第 3 层 · 控制台层（自研 ⭐ 差异化全在这里）                    │
│   智擎 module-cloudops：多租户 + 细粒度 RBAC + 中文 UI        │
│   + 客户/外包账号体系 + 智擎生态集成 + 钉钉/企微通知           │
├─────────────────────────────────────────────────────────────┤
│ 第 2 层 · 引擎层（不重造 ✅ 直接用 Coolify，Apache-2.0）       │
│   Git push 部署 / 多机 SSH 编排 / 280+ 一键服务 / 自动 SSL    │
│   / 数据库一键 / 回滚 —— 控制台通过 REST API 驱动它            │
├─────────────────────────────────────────────────────────────┤
│ 第 1 层 · 节点层（自研薄 agent，只做引擎不做的事）              │
│   node-agent：主机指标上报 / APM 自动注入 / IP 封禁联动        │
│   + 智盾 zhidun（证书签发，已有，零改动）                      │
└─────────────────────────────────────────────────────────────┘
```

**切蛋糕的原则**：社区几千人维护的轮子（部署引擎、容器编排、证书协议）坚决不碰；只有"没人做 + 你有独特资产"的层才自研。

## 2. 差异化从哪来：Coolify 已验证短板 × 智擎已有资产

| Coolify 的短板（有来源） | 智擎的已有资产 | 产品化形态 |
| :--- | :--- | :--- |
| 权限仅 admin/member 两级，细粒度 RBAC 排期 v5（Hetzner 评测） | 智核：tenant_id 多租户 + RBAC + 审计 | **给客户/外包开受限账号**（"你能部署但不能删""你只能看自己项目"）——代理商协作场景刚需 |
| 匈牙利团队，无中文生态 | 母语优势 + 国内交付经验 | 中文 UI/文档、**钉钉/企微通知**、**Gitee 集成**、**DNSPod/阿里云 DNS 泛域名证书** |
| 发布完是黑盒，无应用监控 | monitor-agent（APM 已端到端打通） | **发布模板默认注入 javaagent → 上线即带接口耗时/慢 SQL/异常看板**，独一份 |
| 证书管理仅限本实例 | 智盾 zhidun（REPORT_URL 集中上报，已有） | **多客户/多节点 SSL 统一看板 + 到期预警** |
| 备份/升级粗糙（Hetzner 评测） | 部署/ 工具链 + Rclone 备份经验 | 备份策略模板化、升级演练剧本 |
| 与业务系统完全割裂 | 智擎 ERP/APS/CMS 全家桶 | **私有化交付中台**：卖智擎给制造业客户时，交付/升级/运维成本直接打下来（见 §5） |

## 3. 许可证与开源策略（商业化前必读）

| 组件 | 许可证 | 你能做什么 | 不能做什么 |
| :--- | :--- | :--- | :--- |
| **Coolify** | Apache-2.0 | ✅ 商用、嵌进付费产品、构建 SaaS 在其之上、保留版权说明即可 | 基本没有限制（Apache-2.0 含专利授权条款，比 MIT 更安全） |
| **1Panel** | GPL-3.0 | ✅ 当运维工具用 | ❌ **改它的源码做闭源商业产品**（copyleft 传染）——所以它永远只是过渡件 |
| Uptime Kuma / Beszel / Tailscale 客户端 | MIT / MIT / BSD | ✅ 自由使用与集成 | — |

**开源回馈策略（ reputational leverage ）**：把通用改进 **PR 回 Coolify 上游**——钉钉通知渠道、DNSPod/阿里云 DNS 插件、中文翻译。成本极低，换来的是：社区声誉、上游关系、未来产品发布时的天然流量入口。**开源版（控制台核心 + node-agent）引流，商业版（多租户 SaaS + 私有化授权 + 智擎集成）收钱。**

## 4. 三方案对比与最终选择

| | A. 纯自研（v1 路线） | **B. 控制台 + Coolify 引擎（v2，推荐）** | C. Fork Coolify 深度二开 |
| :--- | :--- | :--- | :--- |
| 开发量 | 大（部署引擎全自研，6 个月+） | **小（只做控制台 + 薄 agent，4-6 周出 MVP）** | 中 |
| 技术栈 | Java（你的栈） | Java 控制台 + API 调用（不碰 PHP） | ❌ PHP/Laravel，非你技术栈，维护地狱 |
| 引擎质量 | 一个人 vs 几千人社区，必输 | 直接获得世界级引擎 + 持续免费升级 | 分叉即冻结，上游红利吃不到 |
| 上游演进风险 | 无 | 通过 API 防腐层隔离，**不 fork 不改源码**，升级可控 | 极大 |
| 结论 | ❌ 重复造轮子 | ✅ **取长补短的正解** | ❌ 最差选项 |

### 4.1 目标架构（三台轻量机）

```
                        ┌──────────────────────────┐
                        │  你的浏览器 / 客户 / 外包   │
                        └────────────┬─────────────┘
                                     │ HTTPS（Tailscale 内网）
              ┌──────────────────────▼──────────────────────┐
              │ 机器 1 · 控制面（建议 2C4G）                  │
              │ ┌────────────────────────────────────────┐ │
              │ │ 智擎平台 + module-cloudops（自研控制台）  │ │
              │ │  多租户/RBAC/审计（智核）+ 中文 UI        │ │
              │ │  统一视图：节点/应用/证书/监控聚合        │ │
              │ ├─ monitor-server（APM :8086）             │ │
              │ ├─ Coolify 引擎（Apache-2.0，容器）◀──────┼─┤ 控制台经 REST API
              │ ├─ Uptime Kuma（对外状态页）               │ │ 驱动引擎
              │ └─ MySQL / Redis / 宿主 Nginx（80/443）    │ │
              └──────┬───────────────────┬─────────────────┘
                     │ Coolify SSH 编排   │ Coolify SSH 编排
        ┌────────────▼───────┐  ┌────────▼────────────┐
        │ 机器 2 · 业务节点    │  │ 机器 3 · 业务节点     │
        │ ├─ Docker 应用群    │  │ ├─ Docker 应用群     │
        │ │  （Coolify 部署） │  │ │  （Coolify 部署）  │
        │ ├─ node-agent 🆕   │  │ ├─ node-agent 🆕    │
        │ │  指标/APM/封禁    │  │ │  指标/APM/封禁     │
        │ └─ zhidun（证书）   │  │ └─ zhidun（证书）    │
        └────────────────────┘  └─────────────────────┘
```

**node-agent 在 v2 中的定位收窄**：部署动作 100% 走 Coolify，agent 只做引擎不做的三件事——主机指标上报、APM 注入执行、IP 封禁联动。从"全栈执行器"瘦身为"差异化补钉"，开发量从月级降到周级。

## 5. 真正的商业模式：不是卖面板，是卖"交付中台"

这是 v2 最重要的上层视角修正。**通用 PaaS 市场你没有胜算，但"智擎产品的私有化交付"是你的独占场景：**

```
你卖智擎 ERP/APS 给制造业客户（私有化部署）
   └── 传统方式：人肉 SSH 到客户服务器装环境、配证书、升级、排障
       每单交付 3-5 天，售后无底洞
   └── 有云管中台后：客户服务器跑一行 node-agent 接入
       → 控制台一键部署智擎全家桶 + 自动 HTTPS + 自带 APM
       → 升级 = 控制台点一下；出问题 = 你在家看 APM 看板
       交付成本砍到小时级，售后从"上门"变"看板"
```

**收入来源**：① 卖智擎时中台作为交付工具（隐性溢价）；② 私有化运维中台按年授权；③ SaaS 托管版按节点收月费；④ 开源版引流建立品牌。Coolify 在这条链路里是**你的供应商，不是对手**——就像你用 MySQL 不和 Oracle 竞争一样。

## 8. 风险与决策点

1. **上游依赖风险**：Coolify 演进快、偶发 breaking changes。对策：只走公开 API（防腐层隔离）、不 fork 源码、生产环境 Coolify 版本固定+灰度升级。
2. **引擎单点**：Coolify 挂了不影响已部署应用运行（配置落在各节点服务器上，无锁定——Apache 社区验证的特性），只影响"新部署"操作。可接受。
3. **node-agent 安全模型**不变：Token 每节点独立可吊销，只执行预定义动作，不执行任意 shell。
4. **nginx 双头管理**：过渡期机器 1 的站点由 1Panel 管、机器 2/3 由 Coolify 管，边界写清楚，逐步收敛到 Coolify。
5. **S 机 2026-12-09 到期 vs 产品进度**：硬期限不能等软进度。对策三件套——①**2026-11-15 检查点**强制决策（控制台就绪走产品迁移，未就绪走 Coolify 引擎直迁，引擎同源不返工）；②**11 月中旬续费 1 个月**做保险丝，把硬期限变软期限；③迁移采用"复制部署→并行验证→DNS 切换"零停机四步法，任何一步失败 S 机仍在服务，可整体回退。

---

## 9. 一句话总结（v2）

**v1 想造一个 Coolify 的对手；v2 想清楚了一个更上层的事实：Coolify 是 Apache-2.0 的世界级引擎，值得做它的"企业管理层"而不是敌人。你的真正护城河从来不在部署引擎——在多租户底座、APM、智盾、中文生态，以及"智擎私有化交付"这个别人进不来的场景。**
